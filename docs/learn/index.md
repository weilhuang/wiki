# 全部学习路径

每条路径有五个实质章节和一份导读。前四章建立合同、机制与证据，第五章把它们组合成一次设计和故障评审。章节可以查阅，但首次学习建议顺序阅读。

## Spring 服务边界

适合能编写 Java 服务、理解异常与 SQL 提交的读者。沿“对象是谁创建的 → 请求是谁完成的 → 数据是谁提交的 → 连接被谁占住 → 整体服务如何评审”推进。

[开始 Spring 路径](/learn/spring-service-boundaries/)。完成产物是对象与资源所有权图、HTTP/数据状态矩阵和短事务服务设计。实验将容器行为、真实回环 HTTP 和 H2 事务分开标注。

## Go 服务生命周期

适合掌握 Go 函数、error、channel 和 goroutine 的读者。沿“入口合同 → 取消传播 → 工作收敛 → 下游预算 → 进程停机”推进。

[开始 Go 路径](/learn/go-service-lifecycle/)。完成产物是入口与错误合同、有界 fan-out、有限重试策略，以及可用真实 main 子进程检验的停机手册。

## 数据一致性

适合理解 SQL、唯一约束和事务边界的读者；不要求同时精通 Java 与 Go。沿“业务不变量 → 未知结果 → 数据与事件交接 → 缓存新鲜度 → 恢复对账”推进。

[开始数据路径](/learn/data-consistency/)。共同场景是订单创建、库存扣减和订单投影。实验使用 MySQL 与 Redis，消息接收端是可控替身；其结果不能替代真实 Kafka/RocketMQ 的交付语义验证。

## 怎样组合阅读

1. 先完成自己熟悉语言的一条服务路径，明确响应、工作完成与提交结果的区别
2. 进入数据路径，给重试、事件和缓存补上持久状态合同
3. 回到原路径终章，修订幂等、恢复和观测设计，说明新增机制的成本

每次只推进一个完整实验，保存预测、实际结果和差异解释。[实验与评审](/guide/practice)说明提交什么证据；[后续规划](/guide/roadmap)列出尚未展开的领域。
