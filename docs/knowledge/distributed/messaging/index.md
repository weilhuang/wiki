# 消息投递与产品机制

[知识目录](/knowledge/) / [消息与分布式](/knowledge/distributed/)

先定义确认含义，再比较队列、日志与消费模型。

## 阅读定位

本地提交、未知结果与稳定操作身份；产品最小背景在正文补足

生产确认、消息保存、投递与消费提交属于不同观察边界；恢复时同时追踪事件身份、进度与业务副作用

## 怎样选择阅读入口

先从幂等与Outbox进入确认边界，再区分队列确认和分区进度，最后用毒消息与按键缺口评审恢复

常见混淆：收到confirm不代表业务完成；重投不必意味着broker错误；输入有序不保证异步业务提交有序

**小目标**：安排一个提交后丢确认的时序，写出broker记录、业务值、副作用条数和未完成工作
