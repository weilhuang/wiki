# Spring 事务

[知识目录](/knowledge/) / [框架与服务通信](/knowledge/frameworks/)

把方法调用映射到连接上的事务，并跟踪正常与异常完成。

## 阅读定位

Java 方法调用和异常、数据库提交/回滚；需要知道调用对象是否由 Spring 提供。

注解保存规则，代理让规则参与一次调用，事务管理器决定加入或新建，连接执行真正提交。异常跨过哪条边界决定哪些状态被记录。

## 怎样选择阅读入口

先从外部结果建立四层模型，再读代理到连接主链；有共享回滚或独立事务问题时转到对应分支，不用从所有传播常量开始背。

常见混淆：自调用绕过当前注解不等于 SQL 一定没有外层事务；catch 也不能清除已经留下的共享回滚标记。

**小目标：**保持 SQL 和异常不变，只改变调用入口，预测最终记录以及调用方会收到什么。
