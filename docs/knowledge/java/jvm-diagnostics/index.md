# JVM 诊断

[知识目录](/knowledge/) / [Java 平台](/knowledge/java/)

从负载和现象提出假设，再选择线程、分配或内存证据。

## 阅读定位

区分请求排队与已经执行；能读方法栈、线程标识和一个时间区间。

线程状态和栈给出采样位置，同一线程的 CPU 增量说明区间内计算活动，GC 日志记录收集事件。三者需要同一观察窗口和业务时间线，单个关键词不够裁决慢请求原因。

## 怎样选择阅读入口

从能主动改变条件的计算、monitor 阻塞和条件等待实验开始，再比较 CPU 时间与分配压力。能区分这些证据之后，再进入实际服务的队列、连接与请求关联。

常见混淆：RUNNABLE 不必然持续使用 CPU；看到 GC 不证明内存泄漏；应用内部 ThreadMXBean 快照不能冒充对未改动进程成功执行的外部诊断。

**小目标**：为 CPU 忙、等待锁和等待下游各列一项支持证据与一项反证，说明下一份采样必须补充哪个身份或时间维度。
