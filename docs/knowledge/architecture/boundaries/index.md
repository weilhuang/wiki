# 建模与边界

[知识目录](/knowledge/) / [系统架构与演进](/knowledge/architecture/)

用责任、依赖方向和数据归属界定模块。

## 阅读定位

能描述一次订单状态变化、函数调用与事务提交；不要求预先选择微服务、分层或某种框架。

模块边界约束代码依赖与责任，数据边界确定谁能修改事实，事务边界确定哪些变化共同裁决，部署边界决定什么可以独立运行。四者可以重合，也可能分开，接口名称不能替代其中任何一个保证。

## 怎样选择阅读入口

先从一条取消规则的变化观察牵连，再比较分层、端口适配器、模块化单体与拆分增加或减少的成本。保留最简单的充分方案；只有共同提交、独立演进或故障隔离等约束改变时，才重新设计结果与失败语义。

常见混淆：同库不等于所有模块都可直接写彼此的表；抽接口不自动隔离变化；mock 全过不能证明数据库回滚；拆进程也不会自动得到自治。

**小目标**：保持取消目标相同，只改变库存能否与订单共同提交这一条件，写出两份决定。分别说明事实所有者、返回含义、失败后的状态和哪一项观察能推翻你的选择。
