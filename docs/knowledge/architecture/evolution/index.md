# 架构演进

[知识目录](/knowledge/) / [系统架构与演进](/knowledge/architecture/)

先判断是否值得变化，再设计可观察、可停止的小步迁移。

## 阅读定位

模块职责、数据归属、一次本地提交的保证，以及跨边界调用的不确定性。

演进保留一段时间的新旧结构。请求路由、写入权、数据复制和发布开关需要分别安排；可逆性取决于已经产生的业务事实。

## 怎样选择阅读入口

先判断是否需要拆分和是否可用更小改动解决，再定义单一写者与回填阶段，最后设计切换、观察和回退。

常见混淆：部署拆开不代表职责清楚；双写不能仅靠调用顺序获得原子性；关闭新代码不会自动撤回已发布事件。

**小目标：**为订单模块给出继续、暂停和回退条件，指出哪一步之后需要前向修复而非代码回滚。
