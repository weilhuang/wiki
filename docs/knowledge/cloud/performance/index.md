# 性能与故障定位

[知识目录](/knowledge/) / [云原生与可靠性](/knowledge/cloud/)

用等待、资源持有与负载区分相似症状。

## 阅读定位

请求与资源的所有权；读具体排障页前知道其指标代表什么。

一次慢请求可能由接纳队列、借用资源、执行或响应等待组成。CPU、连接数量和线程栈观察不同部分，必须用同一窗口关联。

## 怎样选择阅读入口

先界定影响与时间范围，再用能区分假设的最小证据定位；改变一个条件后复核业务结果和资源。负载测试与容量结论另需完整环境。

常见混淆：CPU 不高不等于系统没有瓶颈；延长超时只是延长等待；一张线程栈只能证明采样瞬间的位置。

**小目标：**提出两个都能解释现象的原因，说明哪一项下一步观察可以排除其中一个。
