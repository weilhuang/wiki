# 操作系统

[知识目录](/knowledge/) / [计算机基础与工程方法](/knowledge/foundations/)

进程、虚拟内存和 I/O 提供运行机制的下层解释。

## 阅读定位

会读一个函数调用和资源关闭顺序；先区分进程、线程与一次请求，不要求先学完整内核源码。

程序通过线程执行工作，但请求也可能在队列、锁或 I/O 上等待。进程提供资源与地址空间边界，线程承担执行；一次外部观察通常只说明某个时刻或时间窗口，不能独自裁决业务是否完成。

## 怎样选择阅读入口

先画请求从接纳到结果交接经过哪些对象，再区分执行与等待。用受控输入把两个外观相似的慢请求分开，最后选择线程栈、CPU 时间或资源状态等能回答当前问题的观察。

常见混淆：线程存在不代表它正在占用 CPU；CPU 不高也不代表没有瓶颈；函数返回与外部资源关闭是不同事实。

**小目标**：给同一慢请求提出 CPU 忙与等待资源两个解释，分别设计一项能区分它们的观察，并说明观察还不能证明什么。
