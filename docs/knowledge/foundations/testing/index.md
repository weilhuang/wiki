# 软件测试

[知识目录](/knowledge/) / [计算机基础与工程方法](/knowledge/foundations/)

一个好断言要区分正确实现与相似的错误实现。

## 阅读定位

能读输入、返回值与异常；涉及并发时先识别谁启动工作、谁等待、谁收尾。

测试把一个主张变成可以被反驳的观察。输入安排、时序控制、业务断言和失败归因各自承担一项责任；只有预期的错误被正确观察到，反例才有意义。

## 怎样选择阅读入口

先写出实现不允许破坏的状态，再选择正常例子和外观相似的坏实现。用明确事件安排交错，然后同时核对结果、副作用和清理，最后检查失败是否来自目标错误。

常见混淆：退出码为零不等于业务结果正确；坏实现编译失败也不能证明业务断言有效；一次没有看到竞态不能证明所有时序都安全。

**小目标**：给已有实验改出一个外观仍正常的错误实现，指出具体哪条断言应失败，并证明启动失败不会被它误认成通过。
