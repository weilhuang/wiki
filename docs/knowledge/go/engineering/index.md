# 框架与工程

[知识目录](/knowledge/) / [Go 工程](/knowledge/go/)

用固定模块、明确测试清单与语义反例建立可复现入口，再比较框架增加的状态和责任。

## 阅读定位

能读 Go 接口、error、测试函数和模块文件；值与接口专题提供本实验的业务断言。

源码和依赖图决定执行对象，用例清单决定必须观察的行为，测试工具负责不同层次的证据。unit、race、fuzz 与 benchmark 的绿色结果并不相互替代。

## 怎样选择阅读入口

先固定正确实现与默认运行入口，再用坏实现验证断言，最后选择 race、有限 fuzz 或微基准。真实网络、数据库和框架需要在这个基础上增加各自的环境与结果观察。

常见混淆：exit 0 可能来自少跑测试；编译错误不能证明业务反例被检出；有限 fuzz 不是穷尽证明，短微基准也不是服务容量结论。

**小目标**：从源码包重跑正向与负向检查，再删除一个必需用例，确认验收明确报告缺项而非仍然通过。
