# 事务与并发业务

[知识目录](/knowledge/) / [数据与存储](/knowledge/data/)

以不变量和会话交错判断事务、快照和锁的边界。

## 阅读定位

SQL、唯一约束、提交/回滚，以及两个会话的交错；库存与读视图两篇分别补足业务和版本模型。

不变量约束合法业务状态，事务决定共同提交的写入。普通一致性读按可见性规则选择版本，锁定读取与当前写入则参与此刻的并发裁决；自己的未提交写入还会改变本事务的观察。

## 怎样选择阅读入口

从库存守恒说明想保护的业务事实，再用持续连接区分首次一致性读、RR/RC与当前读取。需要解释候选扫描或锁范围时进入索引，而不是把整套隔离常量当作阅读起点。

常见混淆：库存不为负不能排除超卖；BEGIN 不总是读视图建立点；一次 FOR UPDATE 不会把已有普通快照整体刷新。看见某个数量也不等于仍有权出售它。

**小目标**：让两个会话按明确完成屏障交错，分别预测普通读、锁定读、自身写入、提交与回滚后的两行结果，再说明哪些业务不变量仍需条件写入保护。
