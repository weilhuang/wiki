# 事务与并发业务

[知识目录](/knowledge/) / [数据与存储](/knowledge/data/)

以不变量和会话交错判断事务、快照和锁的边界。

## 阅读定位

SQL、唯一约束、提交/回滚，以及两个会话的交错。

不变量约束合法业务状态，事务决定一起生效的写入，快照决定普通读取看见什么，锁与当前写入决定并发裁决。单独一个表约束往往不能表达跨表守恒。

## 怎样选择阅读入口

先看最短超卖反例，再比较条件更新与锁定读，最后进入访问路径和死锁；本分类从业务问题进入，不冒充完整 InnoDB 总论。

常见混淆：库存不为负不能排除两个订单共享同一份库存；可重复读取不等于仍然有权出售读到的数量。

**小目标：**让两会话竞争一件库存，同时核对库存、订单和业务身份，解释修复把判断放到了哪里。
